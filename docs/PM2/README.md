## How to use this directory

1. Read [`WORKFLOW.md`](WORKFLOW.md) before starting any PM2 work.
2. Pick an open sub-issue assigned to you; its body contains the deliverables and acceptance criteria.
3. Work on a branch from `develop`; do not commit directly to `develop` or `main`.
4. Add the artifact, tests, and evidence; update the Jira task and GitHub issue.
5. Put report-ready material in the matching Part directory and add traceability in Part D.
6. Before the deadline, follow [`SUBMISSION.md`](SUBMISSION.md).

## Non-negotiables

- Jira is authoritative for status, story points, and velocity.
- Every diagram has a `.puml` source and a rendered `.png`.
- Every mocked collaboration has a Moq `Verify`.
- Every claim in the report links to a file, test, run, or Jira issue.
- No secrets, `.env` files, build output, or fabricated evidence.
- The repository tag and commit SHA must match the submitted PDF.
